# 大学生跑步打卡小程序产品需求文档（PRD）

## 1. 产品概述

- **产品名称**：大学生跑步打卡小程序（基于微信小程序 + 云开发）
- **产品类型**：运动记录 / 校园跑步打卡工具
- **目标平台**：微信小程序，使用微信云开发能力（云函数、云数据库、云存储等）
- **一句话介绍**：帮助大学生在校园跑步时轻松完成打卡，自动记录每次跑步的轨迹、距离、时间与配速，并通过排行榜和历史记录见证坚持与进步。

## 2. 目标用户与核心问题

### 2.1 目标用户

- 主要用户：在校大学生，尤其是需要在操场或校园内按要求跑步打卡的学生。

### 2.2 核心问题

- 线下跑步打卡方式分散、麻烦，难以统一记录和统计。
- 传统跑步 App 功能复杂、与校园场景不够贴合。
- 学生难以直观地看到自己长时间坚持跑步的成果和进步。

### 2.3 产品目标

- 提供**简单、清晰、易上手**的跑步记录工具，让学生可以快速完成“选模式 → 开跑 → 结束 → 查看结果”。
- 满足校园体育考核、课程要求等“有目标的打卡”场景。
- 通过**历史记录 + 排行榜**增强成就感和社交激励，促进持续使用。

## 3. 使用场景

1. 学生晚自习后到操场需要完成当日跑步任务，打开小程序快速开始记录，并在结束后向老师展示记录页面。
2. 学生希望系统性地记录自己的跑步里程和配速，观察一周、一月的训练量变化。
3. 同宿舍/同班同学之间通过排行榜对比每天、每月的跑步总里程，产生一点良性“卷”的动力。

## 4. 用户旅程（关键路径）

### 4.1 首次进入 & 首页

1. 用户首次打开小程序，同意必要的授权（定位、运动数据等）。
2. 进入首页，看到校园地图、当前定位点、跑步模式切换标签（如：目标跑、自由跑等）以及中央醒目的“开始/GO”按钮。

**需求条目：**
- 【页面/功能】：用户定位与价值主张  
  【用户行为】：大学生在校园里进行体育场跑步，并需要记录打卡  
  【产品需求】：提供面向大学生的跑步打卡工具，支持记录路径图、距离、时间与配速，满足校园体育考核和自我监督需求  
  【优先级】：高  

- 【页面/功能】：跑步首页首屏  
  【用户行为】：打开小程序看到类似示例图的跑步首页，含地图、跑步模式切换和醒目的启动按钮  
  【产品需求】：首屏展示校园地图实时定位、常用跑步模式标签（如目标跑、自由跑等）以及中央“GO”启动按钮，整体布局参考示例图，突出一键开跑  
  【优先级】：高  

### 4.2 选择跑步模式

1. 用户在首页选择跑步模式，例如：
   - 目标跑：输入或选择预设距离（如 1km、2km、3km 等）。
   - 自由跑：不设定目标，随时可结束。
2. 设置完成后，准备开始运动。

**需求条目：**
- 【页面/功能】：跑步模式选择  
  【用户行为】：首屏首个操作是切换跑步类型（目标距离、自由跑等）  
  【产品需求】：在首页显著位置提供跑步类型切换组件，支持目标跑、自由跑及其他常用模式，并在切换时预览对应配置（如目标距离）  
  【优先级】：高  

### 4.3 开始跑步

1. 用户点击“开始跑步/GO”按钮。
2. 小程序播放 3、2、1 倒计时语音，给用户一个准备时间。
3. 倒计时结束后开始正式记录运动，进入“跑步中”界面。

**需求条目：**
- 【页面/功能】：跑步开始与倒计时  
  【用户行为】：点击“开始跑步/GO”按钮，期待听到 3-2-1 提示音后进入记录状态  
  【产品需求】：启动按钮触发语音倒计时并进入实时记录界面，展示距离、时间、当前配速等数据，同时开始记录 GPS 轨迹  
  【优先级】：高  

### 4.4 跑步中

1. 界面持续展示：
   - 已跑距离
   - 已用时间
   - 当前/平均配速
   - 路线小地图或当前路径
2. 系统在每完成 1 公里时播放语音提示：报读当前公里数，并进行简单鼓励。
3. 用户可以随时点击“暂停”，短暂停留后再继续，或在暂停状态下选择“结束运动”。

**需求条目：**
- 【页面/功能】：跑步中语音提醒  
  【用户行为】：在跑步过程中每公里收到语音里程提醒与鼓励  
  【产品需求】：记录界面后台监听里程，每完成 1 公里播放提示与鼓励语音，强化跑步动力  
  【优先级】：中  

- 【页面/功能】：跑步过程中途控制  
  【用户行为】：跑步时可随时点击暂停，再继续或结束  
  【产品需求】：实时记录界面提供醒目的暂停/继续按钮，暂停时保持数据不丢失并提示当前为“暂停中”，继续后无缝接上记录  
  【优先级】：中  

### 4.5 结束跑步 & 结果页

1. 用户在跑步中或暂停状态下，点击红色“结束运动”按钮确认结束。
2. 系统生成本次运动记录，展示：
   - 跑步轨迹（地图）
   - 总距离
   - 总时间
   - 平均配速
   - 消耗能量（可选）
3. 同时展示每日 / 每月跑步距离排行榜，帮助用户对比自己与其他同学的表现。

**需求条目：**
- 【页面/功能】：结束总结与排行  
  【用户行为】：点击红色“结束运动”按钮，查看轨迹、距离、时间、配速，并浏览每日/每月排行榜  
  【产品需求】：结束页展示完整运动摘要与地图轨迹，并附带按日/月累计距离的排行榜，支持查看自己在排行榜中的位置  
  【优先级】：高  

### 4.6 历史记录 & 回访

1. 用户在非运动时再次打开小程序，可以从“记录/我的”入口进入历史记录页。
2. 历史记录页按日期/周/月展示运动列表和统计图表，用户可以查看每一次的详细记录和整体趋势。
3. 用户通过看到自己累积的总里程与坚持天数，更有动力持续回来使用。

**需求条目：**
- 【页面/功能】：运动记录回顾  
  【用户行为】：结束后回到历史记录，查看过去跑步数据以见证坚持与进步  
  【产品需求】：提供按日期/周/月的历史记录列表与可视化统计（如柱状图、累计里程），支持点进单次记录查看轨迹和详情  
  【优先级】：中  

### 4.7 异常与风险提示

目前期望流程较为顺畅，没有明显困惑点，但需要在出现异常时给出清晰提示。

- 【页面/功能】：流程风险提示  
  【用户行为】：跑全程未遇到明显困惑节点  
  【产品需求】：在 GPS 信号弱、网络中断、定位权限被关闭等情况下，弹出清晰提示，说明问题并引导用户如何处理，避免数据丢失或误解  
  【优先级】：低  

## 5. 功能需求列表（按模块整理）

### 5.1 账号与基础信息

- 使用微信 OpenID 作为用户唯一标识。
- 可在“我的”页面展示昵称、头像，绑定学校/班级（可选，用于排行榜分组）。
- 新增**显式微信登录流程**：
  - 首次进入小程序时弹出欢迎/授权页面，说明“使用微信登录以同步跑步成绩”，按钮采用 `getUserProfile` 拉起微信授权。
  - 登录按钮点击后触发 `wx.login` + `wx.getUserProfile`，客户端把 code + 微信基础资料（头像、昵称、性别、国家/省份/城市）上传后端换取会话 `sessionToken`。
  - 登录成功自动跳转首页，未登录状态无法开始跑步或查看排行榜，必要操作时弹出“请先微信登录”提示。
  - “我的”页面提供退出登录 / 重新授权入口，可重新同步头像昵称。

### 5.2 首页 & 跑步模式

- 显示校园地图与当前位置。
- 提供跑步模式切换（目标跑、自由跑，可预留更多模式）。
- 显示“开始/GO”主按钮。
- 必要时展示天气、GPS 状态等辅助信息（可选）。

### 5.3 运动记录（跑步中）

- 实时记录与展示：距离、时间、配速、轨迹。
- 1 公里语音提醒与鼓励。
- 暂停、继续、结束控制。
- 异常情况提示（GPS 信号弱等）。

### 5.4 运动结果页

- 本次运动的完整数据与可视化展示。
- 可添加简单勋章/评价文案（如“今日第一跑”“配速提升了”）。

### 5.5 排行榜

- 按**每日**、**每月**统计用户总里程。
- 默认展示同校/同班的排行榜（若有绑定信息），否则展示全体用户榜单。
- 高亮当前用户排名与数据。

### 5.6 历史记录

- 以列表展示每次运动的日期、距离、时间等关键数据。
- 支持按日、周、月聚合统计（如累计里程、总次数）。
- 点击单次记录可查看详细轨迹与当次数据。

### 5.7 设置

- 语音提醒开关（可关闭 1 公里语音提示）。
- 单位设置（公里/配速显示格式）。

## 6. 非功能性需求

### 6.1 性能

- 跑步过程中数据刷新与地图渲染需保持流畅，避免明显卡顿。
- 单次运动记录时长可支持至少 2 小时以上不中断。

### 6.2 稳定性

- 在网络不稳定时，优先保证本地数据缓存，待网络恢复后再同步到云端，防止记录丢失。

### 6.3 安全与隐私

- 仅在运动记录时使用定位权限，说明用途并获得用户授权。
- 运动轨迹等数据仅对本人可见，排行榜只展示昵称和里程等非隐私信息。

### 6.4 兼容性

- 适配主流机型与常见系统版本，确保基础功能可用。

## 7. 数据结构（示意）

> 实际字段可在开发阶段结合微信云开发数据库进行细化，这里先给出核心字段示意。

### 7.1 用户表（users）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键，自增 |
| open_id | varchar(64) | 微信 OpenID，唯一索引 |
| nickname | varchar(64) | 微信昵称，登录时同步，可编辑 |
| avatar_url | varchar(255) | 头像链接 |
| gender | varchar(16) | 性别（male/female/unknown），来自微信资料 |
| country | varchar(64) | 国家（可空） |
| province | varchar(64) | 省份（可空） |
| city | varchar(64) | 城市（可空） |
| school | varchar(64) | 学校（可空，用户维护） |
| class_name | varchar(64) | 班级（可空，用户维护） |
| voice_enabled | tinyint(1) | 是否开启语音提醒，默认 1 |
| last_login_at | datetime | 最近一次登录时间，便于统计活跃 |
| created_at/updated_at | datetime | 审计字段 |

### 7.2 运动记录表（runs）

- runId
- userId
- dateTimeStart
- dateTimeEnd
- duration
- distance
- avgPace
- calories (可选)
- gpsTrack（坐标点数组）
- mode（目标跑/自由跑等）

### 7.3 统计表/视图（stats）

- userId
- date (按日)
- month (按月)
- totalDistance
- totalRuns

## 8. 里程碑建议

- **版本 V1（核心功能）**：
  - 首页 + 跑步模式选择
  - 开始/结束跑步记录、轨迹记录
  - 跑步中数据展示、1 公里语音提醒
  - 结束页展示数据
  - 历史记录列表

- **版本 V1.1（增强体验）**：
  - 日/月排行榜
  - 简单统计图表
  - 设置页面（语音开关等）
